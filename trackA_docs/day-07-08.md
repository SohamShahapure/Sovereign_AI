## 1. How it works

```bash
uv run python -m eval.build_questions
```

| File | What it is |
|---|---|
| `eval/question_bank.py` | **Source of truth.** Each question with its type, reference answer and source page(s), each source with *evidence* quotes copied from the page. Edit this, then rebuild. |
| `eval/build_questions.py` | Parses the cited PDFs and fails if any evidence quote is missing from its cited page. Writes the three files below. |
| `eval/questions.jsonl` | Contract 3.4: `{id, question, answer, source_doc, source_page}`. Track B uses this. |
| `eval/questions_meta.jsonl` | Same ids, plus `type` and every source with `evidence` and `accept_pages`. Used by the Days 9–10 scorer. |
| `eval/review.md` | One block per question with the evidence in context, plus a checkbox for review. |

**Evidence makes page numbers checkable.** For example, q008 (HDFC Bank final dividend) cites p.251
with evidence `"recommended a final dividend of"` + `"13.00 (Rupees Thirteen only)"`. If either
string isn't on p.251, the build fails. The check is case- and whitespace-insensitive and runs on
the same parsed text the index uses. It also caught one ambiguity while writing the set: Kotak's
p.17 infographic shows consolidated and standalone profit without clear labels. That question now
cites p.192 of the standalone financial statements instead.

**Accepted pages.** Annual reports repeat headline facts (highlights, Board's report, MD&A). For
each source, the builder lists every page of that report containing *all* its evidence strings. 17
sources have more than one such page. Retrieval will count any of them as a hit, so finding the
same fact on another page isn't scored as a miss.

## 2. What's in the set

| Type | Count | What it tests | Example |
|---|---:|---|---|
| `lookup` | 21 | Names and firms: leaders, auditors, a date | Who are Reliance Industries' statutory auditors? |
| `numeric` | 41 | One figure, with its unit | What dividend per share did SBI declare for FY2025-26? → ₹17.35 |
| `multi_part` | 14 | Two or three facts from one report | Reliance's revenue, EBITDA *and* net profit |
| `cross_company` | 11 | Facts from two reports, often compared | Which bank had the higher capital adequacy ratio, HDFC Bank or Kotak? |
| `not_found` | 13 | The model must say it can't find it | What was Larsen & Toubro's order book? |

Questions with sources come from every report (HDFC Bank 18 sources, Tata Steel 10, HCLTech 9,
Bajaj Auto 9, SBI, Kotak, Reliance, Wipro, Asian Paints 8 each, Sun Pharma 7, Airtel 6). HDFC
Bank is overrepresented because its report is the longest and appears in four cross-company
questions.

**The 13 "not found" questions come in three kinds:**
- **Companies named nowhere in the 11 reports** (checked with a corpus search): L&T, UltraTech,
  Zomato, Hero MotoCorp, Cipla, Vodafone Idea.
- **A trap: Infosys.** It is mentioned 7 times (a former Infosys CFO on HDFC Bank's board, an
  Infosys Finacle award, employees' previous employers in Wipro's report), but no report states its
  revenue. Retrieval will surface those pages, and the model has to refuse anyway.
- **Periods after the reports were published** (FY2026-27 results, prices in December 2026,
  September 2026 ratios). The reports can't contain these.

Their reference answer is the exact `NOT_FOUND` sentence from `rag/prompt.py`, and their
`source_doc`/`source_page` are `null`.

## 3. Design decisions

| Decision | Why |
|---|---|
| **Questions written from the documents, not from retrieval results** | If questions were picked because the retriever finds them, the eval would measure nothing. All questions came from regex searches of the parsed text, never from `rag.search`. |
| **Contract file kept to exactly 5 fields; extra data in a separate file** | Contract 3.4 is shared with Track B. Adding fields there would be a contract change; a separate `questions_meta.jsonl` keyed by `id` isn't. |
| **`source_page` = 1-based PDF page index** | The same number `/ask` returns in citations, so hit@5 compares like with like. Still an open contract change request; Track B doesn't read `source_page`, so it doesn't block them. |
| **Evidence never includes the rupee sign** | Several PDFs encode ₹ as `` ` ``, `H`, `I`, `J` or `K`, so evidence uses the digits and words around it |
| **Reference answers keep the report's number format** | ₹2,11,178 or 211,178? The answer keeps the report's form (Indian or international grouping), so a reviewer can match it to the page. The scorer in Days 9–10 must normalize both forms. |
| **Questions in the bank are grouped by company** | Easy to review and extend. A quick dev subset should take every 10th question, not the first 10. |

## 4. To review (needed for "done")

Open `eval/review.md`. For each question, check that:
1. the question is clear and has a single right answer,
2. the reference answer matches the quote,
3. the cited page is right. Open the PDF at that page number in a viewer (PDF page, not the
   printed number).

Tick `- [x] reviewed` when done. If something is wrong, fix it in `eval/question_bank.py` and
rebuild. (The tick boxes are overwritten by a rebuild, so review in one sitting or note the ids.)

## 5. Next: Days 9–10 (scoring)

One command that runs all 100 questions and prints a score table:
- **Retrieval hit@5** from `accept_pages`. For multi-part and cross-company questions, every source
  must have one accepted page in the top 5.
- **Answer correctness**: numeric match (normalizing ₹, crore/lakh grouping and %) plus LLM-as-judge
  for text answers. `not_found` scores by exact match on the refusal sentence.
- **Faithfulness**: is the answer supported by the pages it cites?
- **Paid-API baseline** (GPT or Claude) on the same questions, plus cost per 1,000 queries.

Results get saved in contract 3.3 format to `bench/results/`. On CPU, the full 100 through Ollama
takes about 2–3 hours, so use a subset of every 10th question while developing.
